1. 结论速览

最小可用路径：pnpm install → pnpm build:wasm → pnpm dev → 浏览器打开 http://localhost:5173。

这个仓库是一个 pnpm monorepo，但根目录的 pnpm dev 只启动 Web 编辑器（apps/web）。用户之前执行的 pnpm install 与 pnpm dev 只完成了依赖安装和 Vite 启动；如果新克隆后没有执行 pnpm build:wasm，部分音频/频谱功能会缺少 WASM 产物。

核心 Web 应用

apps/web，React 19 + TypeScript + Vite。编辑器、欢迎页、AI 对话、协作、导出等 UI 均在这里。

核心引擎

packages/core，时间线、动作执行、渲染、字幕、导出等领域引擎；通过源码别名直接被 web 引用。

生产托管

Cloudflare Pages，项目名 openreel；产物目录 apps/web/dist；SPA 重写与安全头已随仓库提供。

重要提醒

仓库 README 写 5173，start.sh 写 5174；二者并不冲突，start.sh 只是额外指定了端口。

2. 环境与前置依赖

项目要求说明
Node.js≥ 18；推荐 22 LTS根 engines.node 为 >=18，CI 使用 Node 22。
pnpmpackageManager 锁定 11.7.0根 package.json 指定；CI 用 pnpm/action-setup@v4 自动解析。
浏览器Chrome/Edge 94+ 推荐依赖 WebCodecs / WebGPU；无 WebGPU 时回退 Canvas2D。README 标注 Firefox 130+、Safari 16.4+。
内存/GPU8GB+，4K 建议 16GB+4K 剪辑建议独显；纯 CPU 环境可运行但性能有限。
ffmpeg测试/E2E 与桌面包需要Web 主链使用 ffmpeg.wasm；CI 单测和 E2E 会调用系统 ffmpeg/ffprobe。
xmllint运行完整单测需要FCPXML/XMEML 交换格式测试依赖 libxml2-utils，缺失会失败而非跳过。
WASM 工具链仅需 AssemblyScript（npm 包）主链 pnpm build:wasm 不需要 Rust/Emscripten/Go。
Cloudflare Wrangler部署 Pages/Worker 需要已作为 web/cloud/image 的 devDependency 安装，首次需登录授权。

2.1 启用 pnpm

node --version
corepack enable
corepack prepare pnpm@11.7.0 --activate
pnpm --version

如果本机没有 Corepack，也可以直接 npm install -g pnpm@11.7.0。CI 与本地都建议遵循 packageManager 字段，避免 lockfile 版本漂移。

不要跳过 pnpm build:wasm。 三个 WASM 产物没有被提交到仓库，且被 .gitignore 忽略；新克隆后必须显式构建。

3. 首次本地部署（推荐流程）

克隆仓库

git clone https://github.com/Augani/openreel-video.git
cd openreel-video

安装依赖

pnpm install

该命令会按 pnpm-workspace.yaml 安装 apps/* 与 packages/*，并应用两个 ffmpeg 补丁：

@ffmpeg/core@0.12.6      → patches/@ffmpeg__core@0.12.6.patch
@ffmpeg/core-mt@0.12.6 → patches/@ffmpeg__core-mt@0.12.6.patch

CI 环境使用 pnpm install --frozen-lockfile；本地首次部署也建议保持 lockfile 不被改动。

构建 WASM 模块

pnpm build:wasm

该命令实际执行 asc（AssemblyScript）三次，生成：

packages/core/src/wasm/fft/build/fft.wasm
packages/core/src/wasm/wav/build/wav.wasm
packages/core/src/wasm/beat-detection/build/beat.wasm

启动开发服务器

pnpm dev
# 打开 http://localhost:5173

等效于 pnpm --filter @openreel/web dev。Vite 配置在 dev 与 preview 阶段注入 COOP/COEP 响应头，以支持 SharedArrayBuffer。

可选：使用仓库自带启动脚本

./start.sh
# 固定使用 http://localhost:5174

start.sh 的 WASM 检查路径写成了 packages/core/src/wasm/build，与实际产物路径不一致，因此它几乎总会重新执行 pnpm build:wasm。这不是致命问题，只是多做一次构建。

如果 5173 端口被占用 
pnpm dev -- --port 5174

注意 apps/image 和 apps/studio 的默认端口也是 5174，同时启动多个应用时需错开端口。

6.1 API 代理策略

apps/web/src/services/api-proxy.ts 统一封装第三方 API 调用：

  • 开发环境：直连 ElevenLabs / OpenAI / Anthropic 等内置服务。
  • 生产环境：内置服务走同源 /api/proxy/<service>/<path>，由 Cloudflare Pages Function 转发。
  • 用户自定义兼容端点：始终直连，避免把托管代理变成任意目标中继。
  • 桌面端：通过 window.openreel.cloud.fetch 走主进程桥接。

7. Web 生产构建与部署

7.1 构建与本地预览

pnpm build
pnpm preview
# 默认 http://localhost:4173

pnpm build 的顺序为：

  1. pnpm build:wasm：生成三个 WASM。
  2. pnpm --filter @openreel/web build：先运行 tsc --noEmit，再运行 vite build。
  3. 产物输出到 apps/web/dist（Vite 默认，且与 wrangler.toml 的 pages_build_output_dir = "dist" 一致）。

7.2 部署到 Cloudflare Pages

pnpm --filter @openreel/web exec wrangler login
pnpm deploy:preview
# 或
pnpm deploy
配置项值文件
Pages 项目名openreelapps/web/package.json
Preview 项目名openreel-previewapps/web/wrangler.toml
产物目录distapps/web/wrangler.toml
兼容性日期2024-01-01apps/web/wrangler.toml
SPA 重写/* /index.html 200apps/web/public/_redirects
安全/CORP 头COOP same-origin、COEP require-corp、nosniff、DENY、Referrer-Policyapps/web/public/_headers

CI 中没有自动部署 Web 的步骤；ci.yml 的 build job 只执行 pnpm build。发布需要人工执行 pnpm deploy / pnpm deploy:preview，或由外部平台触发。

自定义域注释：app.openreel.video 对应标准编辑器；motion.openreel.video 当前回退到标准编辑器，因为 Web 特性配置中 Motion Creator 处于关闭状态。

8.1 桌面端打包

pnpm --filter @openreel/desktop pack   # 目录形式，--dir
pnpm --filter @openreel/desktop dist   # 完整安装包
  • build:renderer 会设置 OPENREEL_DESKTOP=1 后重建 web renderer。
  • build:main 用 tsup 构建主进程、preload、Aurora host、MCP shim。
  • pack / dist 会先执行 fetch:ffmpeg，按固定 SHA256 下载 ffmpeg sidecar；这些二进制被 git 忽略。
  • 原生 Aurora renderer 由 prepare-aurora-native.mjs 从 packages/creation-core/build 复制；缺失时跳过并有 CPU fallback。

8.2 独立资源部署脚本

  • scripts/filters/deploy.sh：上传 .cube 滤镜与 manifest 到 R2，默认 bucket openreel-filters、域名 https://filters.openreel.video。
  • scripts/upload-vidstab-r2.sh：上传 ffmpeg-vidstab core 到 pub-openreel bucket。
  • packages/creation-core 的原生/WASM 构建独立于此链路；需要 CMake/C++20 / Emscripten，仅在做原生创建引擎开发时才需要。

9. CI/CD 流程

工作流触发主要步骤
.github/workflows/ci.ymlpush / PR 到 main、feat/ios-apptest → build → perf-smoke → e2e（10 shard）。
ci.yml#test同上Node 22、frozen lockfile、安装 xmllint/ffmpeg、typecheck、lint、build:wasm、test。
ci.yml#build依赖 test安装依赖后执行 pnpm build。
ci.yml#perf-smoke同上build:wasm → web build → bundle:budget → perf:gate。
ci.yml#e2e同上ubuntu-24.04 + Google Chrome，端口 5391，按 shard-plan.mjs 分 10 片跑。
.github/workflows/release.ymltag v* 或手动quality → 三平台 build → manifest → 上传 R2；macOS 签名/公证。
desktop-readiness.yml桌面相关桌面 typecheck/test + 真 Electron/ffmpeg 套件。
perf-gate.yml定时/手动Web 性能与桌面包体预算。

E2E 使用 Google Chrome 而非 Playwright 自带 Chromium，原因是 Linux 版 Chromium 缺少 H.264/AAC 等专有编解码器，会影响导出、多机位、代理和字幕相关用例。

11. 故障排查

11.1 页面空白或控制台报 WASM 404

先确认是否已执行 pnpm build:wasm，再检查三个产物路径。不要只依赖 start.sh 的路径判断，它的检查目录与实际产物目录不一致。

11.2 报 SharedArrayBuffer 不可用

开发/预览阶段由 Vite 的 server.headers / preview.headers 注入 COOP 与 COEP；生产阶段由 public/_headers 提供。如果你用自建反向代理托管 dist，必须自行补上：

Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
11.3 pnpm install 报 ffmpeg patch 失败

确认 pnpm-workspace.yaml 中两条 patchedDependencies 与 patches/ 目录文件都存在，并使用仓库自带 pnpm-lock.yaml。不要删除 lockfile 后重装，也不要关闭 patches。

11.4 端口冲突

Web 默认 5173；image/studio 默认 5174；cloud worker 8787；E2E 5391。可使用 pnpm dev -- --port 5174 临时调整 Web 端口，或停止占用端口的进程。

11.5 单测或 E2E 因外部命令失败

安装系统依赖：macOS 可用 brew install ffmpeg；Ubuntu 可用 sudo apt-get install -y ffmpeg libxml2-utils。E2E 还需 pnpm --filter @openreel/web exec playwright install --with-deps chrome。

11.6 没有 WebGPU，预览是否正常？

应用设计了渐进增强：无 WebGPU adapter 时回退到 Canvas2D；CI 的无 GPU 环境也依赖此路径。功能可用，但 4K/复杂特效性能会下降。

11.7 界面没有中文

当前 Web 应用没有实现 UI i18n：依赖中没有 i18n 框架，源码中也没有语言包或语言切换入口，首屏与编辑器文案是硬编码英文。settings-store 中的 language 字段不是界面语言开关。需要额外实现翻译层与中文语言包，重装依赖不会自动中文化。详见 源码分析文档中的说明。

11.8 桌面端缺少 ffmpeg / 原生渲染器

执行 pnpm --filter @openreel/desktop fetch:ffmpeg 下载 sidecar；原生 Aurora renderer 由 prepare:aurora 尝试复制，缺失时使用 CPU fallback，不影响启动。

11.9 新建的 docs 文档没有被 git 跟踪

仓库 .gitignore 默认忽略 docs/*，只放行少数目录。本文与配套源码分析文档已通过白名单规则放行，若你新增其他文档，也需要添加对应的 !docs/xxx 规则。
